# 02. Спецификация

Запиши spec.md в workspace по [шаблону](skill://tospec/templates/spec.md). Документ для
агента, человеческой части в нём нет; объяснение для пользователя — в чате
(шаг 03). Область и правила описывай для реальной задачи. Существенные наблюдения
опыта клади в F с условиями и пределом вывода, без журнала и выдуманных запусков.

Опиши проблему, границы, поведение, сценарии, R-требования и AC-приёмку. Каждое R
опирается на U или на решение D внутри U; каждое AC — на R. Примеры и исключения
не вводят скрытого поведения. F подтверждает факт, но не заменяет поручение
пользователя.

Для каждого самостоятельного проектного решения зафиксируй D и вид:
- ПРЯМОЕ — точное указание пользователя U.
- ВЫНУЖДЕННОЕ — другой допустимый вариант нарушает действующее условие; назови
  его. Удобство, привычка и готовая библиотека единственность не доказывают.
- ВЫБОР — есть альтернативы; рекомендуй самый простой достаточный вариант по
  Gold Standard, кратко назови отклонённые и причины.

Новые решения пока предложены. Проектирование пользователю не возвращай: каждый
ВЫБОР несёт рекомендацию и реальные альтернативы для вопроса в 03. Существенный
неизвестный факт — Q; спрашивай через `ask`, только если исследованием его не
получить.

Детализируй нужное для результата: условия, данные, интерфейсы, ошибки,
ограничения, проверяемые исходы. Лимиты, миграции, безопасность, fallback, тесты,
инфраструктуру и редкие случаи ради качества не добавляй. Применимый обязательный
контракт указывай с источником. Метрики и запуски для уверенности не нужны; опыт
— только по 01.

Сверяй условия пользователя и основания D при записи; отдельным проходом файл не
перечитывай. Для ВЫНУЖДЕННОГО убедись, что альтернативы действительно нарушают
условие, иначе это ВЫБОР.

Первое предъявление — v1. Один пользовательский раунд содержательных поправок
повышает vN один раз; несколько поправок до следующей подачи — один раунд.
Внутренний fix номер не повышает, но новый смысл или решающий факт снимает
готовность плана; старое согласие сохраняется только для неизменённого смысла.
Перепроверку правки задаёт review.

Выход: черновик с основаниями всех R/AC/D, без скрытого scope и плана работ.
Далее 03; reviewer до согласия не запускай.
