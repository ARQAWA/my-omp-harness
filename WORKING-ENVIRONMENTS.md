# Рабочие окружения

Условия окружений, в которых работает harness. Установка и работа всех
компонентов обязаны их соблюдать.

## Windows только внутри VS Code

Windows без прав администратора и без WSL. Всё, что ставит этот репозиторий,
работает здесь только внутри VS Code дочерними процессами extension host
расширения VS Code. Это обязательное условие без исключений.

- Цепочка процессов: VS Code → extension host → `herdr server` → Git Bash → omp →
  агенты и их команды. Клиент herdr — тоже дочерний процесс extension host.
- Напрямую на хосте ничего не запускается: ни в отдельном окне PowerShell, cmd
  или Windows Terminal, ни ярлыком, службой, задачей планировщика или через WMI.
  Команды установки и проверок выполняет агент, который сам работает внутри VS
  Code.
- herdr запускает только расширение VS Code: оно стартует `herdr server` своим
  дочерним процессом и показывает `herdr client` в своём псевдотерминале. При
  закрытии VS Code расширение останавливает сервер вместе с окнами. Расширение
  сейчас проходит тест и в репозиторий не входит.
- `herdr` без аргументов и `herdr server` вручную не запускай: `herdr` без
  работающего сервера запускает сервер отвязанным, а иногда через WMI, то есть
  вне дерева VS Code.
- omp работает только в окне herdr, поэтому порядок установки другой: сначала
  herdr и расширение, затем omp ставится, запускается и входит в провайдеров в
  окне herdr, после этого выполняется `herdr integration install omp`.
