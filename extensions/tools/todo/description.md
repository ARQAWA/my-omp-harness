Keep a list for every task except one answer or one short action, and always for work that ends in a review. Create or extend it before the first action, plan the work before doing it and mark progress as it happens, never after the fact. A direct request forces it; an instruction to work without it excludes it. Put todo calls in the same response as your other tool calls; never spend a response on todo alone.

- The list holds the plan and the decisions that keep the stages consistent, not the gathered context. Plan every stage you understand as items; when you start an item, give it a plan: its concrete steps in order, with the draft decisions they carry, such as where each piece of code goes and its interfaces. Mark the current step with `step`. When a finding changes the plan, rewrite the affected future items. Put a finding you will need again, such as a mapped flow or a decision with its reasons, in its own `local://<subject>.md` file and name that file in the item; after a context loss, read the files the list names before continuing.
- Write phases, items and steps in Russian, keeping technical names, paths and commands as they are; always start a list with `init` and a named phase.
- Each item is a concrete outcome from the request: what will be true, in which artifact or behavior, and what establishes that it is done. Rewrite an activity such as "keep investigating" into an outcome. A metric, test, command or run count written into an item authorizes nothing.
- Extend an unfinished list with `append` for continued work; after a fully closed list, `init` the next multi-step task. When the work moves to a different task, drop the old list's remaining items first.
- At handover every item is done, dropped as no longer needed, or blocked with its reason. When a turn ends with a blocked item, the last message says the plan cannot be finished, which blocker needs resolving and that you wait for the user. You cannot finish while items are pending or in progress. A blocker, a wait or a turn end is not completion: an item is done only when its result is.
